# ESP32-CAM: план проекта

## Цель
Запустить ESP32-CAM (с платой ESP32-CAM-MB) и протестировать камеру. Это первый этап более крупного проекта — умного кошачьего лотка.

## Итоговая идея (общий проект)
- Несколько датчиков давления определяют, какой из трёх котов зашёл в лоток (по весу/паттерну давления).
- ESP32-CAM делает фото в момент события.
- Данные (показания датчиков, идентификация кота, фото) отправляются по MQTT на собственный сервер (брокер).

## Этап 1: запуск и тест камеры — ✅ пройден (2026-09-01)
1. ✅ Прошить ESP32-CAM через ESP32-CAM-MB (USB-UART переходник, кнопка загрузки не нужна благодаря MB).
2. ✅ Настроить PlatformIO для ESP32-CAM.
3. ✅ Залить тестовый пример камеры и получить видеопоток/фото через веб-интерфейс.
4. ✅ Оценить качество изображения — устраивает, менять модуль камеры не требуется.
   Сенсор на плате оказался **OV3660** (не OV2640, как предполагалось изначально) —
   код автоопределяет сенсор, ничего дорабатывать не пришлось.
5. Стабильность (питание, нагрев, долгая работа WiFi) — пока проверено только
   на коротких сессиях, длительный прогон ещё предстоит.

**Архитектурное решение**: проект переведён на PlatformIO + framework `espidf`
(не Arduino), чтобы напрямую переиспользовать уже готовый и проверенный код
Wi-Fi/NTP/TLS+MQTT из соседнего проекта `~/MyFiles/Microcontrollers/ESP32`
(тот же брокер `mrmixfon.ru:8883`, тот же CA, топики `home/{room}/...`).
Это сразу закладывает инфраструктуру связи, которая понадобится на Этапе 4,
и даёт единообразие между устройствами будущей системы. Детали — в
`NEXT_STEPS.md`.

## Этап 2: датчики давления
- Подобрать и подключить датчики давления (по одному на зону/кота или один общий с анализом паттерна).
- Собрать данные, откалибровать пороги для различения трёх котов по весу/характеру давления.
- Написать логику определения "кто зашёл в лоток".

## Этап 3: интеграция камеры + датчиков
- По срабатыванию датчика — триггерить снимок камерой.
- Синхронизировать событие датчика с фото (для верификации/датасета).

## Этап 4: передача данных по MQTT
- Поднять MQTT-брокер на своём сервере (например, Mosquitto).
- ESP32-CAM/ESP32 публикует:
  - показания датчиков давления,
  - результат идентификации кота,
  - фото (как файл/base64 или через отдельный canal, т.к. MQTT не оптимален для больших бинарников — рассмотреть HTTP upload для фото + MQTT для метаданных).
- Разработать формат сообщений (JSON: timestamp, cat_id, sensor_values, photo_url).

## Этап 5: доработка и эксплуатация
- Логирование и мониторинг на сервере.
- Обработка ошибок сети/переподключение MQTT.
- (Опционально) дальнейшая аналитика: частота посещений, вес по времени и т.д.

## Открытые вопросы / решения по ходу
- Итоговый способ идентификации кота (только давление, или + другие сенсоры).
- Формат хранения и передачи фото.
- MQTT-брокер (`mrmixfon.ru:8883`) на стороне сервера сейчас намеренно
  отключён пользователем на время работы над камерой — заработает снова
  ближе к Этапу 4, отдельного действия в прошивке для этого не требуется
  (esp-mqtt переподключается сам).
