## Статус

**Этап 1 (запуск + тест камеры) пройден.** Прошито и проверено на реальном
железе 2026-09-01: WiFi подключается, NTP синхронизируется, HTTP-сервер
отдаёт кадры. Камера на этой плате — **OV3660** (не OV2640, как
предполагалось изначально; определяется автоматически, код универсален).
Качество картинки проверено через `/capture` — пользователя устраивает,
менять модуль камеры не требуется.

MQTT пока **намеренно отключён** пользователем на стороне брокера — в логе
будет `Ошибка MQTT` / `esp-mqtt переподключится сам`, это ожидаемо и не
является поломкой прошивки. Когда брокер снова будет доступен, esp-mqtt
переподключится сам, без переприошивки.

## Как прошить и проверить заново

```
source secrets.sh
pio run -t upload
pio device monitor
```

В логе должно быть: инициализация камеры → подключение Wi-Fi → NTP →
`HTTP server started`. Дальше открыть `http://<IP-устройства>/` в браузере —
MJPEG-стрим; `http://<IP-устройства>/capture` — один JPEG-кадр.

## Что уже сделано

- Камера (`src/camera.c`) — AI-Thinker пины, автоопределение сенсора
  (OV3660 на этом модуле), PSRAM-буферы кадров.
- HTTP-сервер (`src/http_server.c`, `esp_http_server`) — `/`, `/capture`,
  `/stream` для визуальной проверки качества картинки без MQTT.
- Wi-Fi, NTP, TLS+MQTT (`src/wifi.c`, `src/time_sync.c`, `src/mqtt.c`) —
  перенесены как есть из проекта `ESP32` для единообразия и переиспользования
  уже проверенной логики (тот же брокер, топики `home/{room}/...`, Last Will).
- `sdkconfig.defaults`: 4MB flash, PSRAM включён, увеличенная таблица
  разделов (`partitions_singleapp_large.csv`) — камера + mbedTLS + HTTP не
  влезали в стандартный 1MB app-раздел.
